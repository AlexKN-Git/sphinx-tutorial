# 9. CI и публикация

```{note}
CI (Continuous Integration) — это автоматическая сборка проекта на сервере
при каждом изменении. Обычно — при push в Git и при pull request.
```

## Зачем

- Автоматическая проверка, что документация собирается без ошибок.
- Публикация сайта одним нажатием.
- Одинаковая среда сборки у всех разработчиков и на CI.

## GitHub Actions — базовый сценарий

Создай в корне репозитория файл `.github/workflows/docs.yml`:

```yaml
name: Build and publish docs

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.12'
      - name: Install dependencies
        run: pip install -r requirements.txt
      - name: Build HTML
        run: sphinx-build -b html docs docs/_build/html
      - uses: actions/upload-pages-artifact@v3
        with:
          path: docs/_build/html

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Что происходит:

1. Workflow запускается при push в `main` и вручную через `workflow_dispatch`.
2. Job `build` разворачивает Ubuntu, ставит Python 3.12, ставит зависимости
   из `requirements.txt`, собирает HTML.
3. Артефакт сборки (`docs/_build/html`) сохраняется как GitHub Pages artifact.
4. Job `deploy` публикует артефакт на GitHub Pages.

## Включение Pages в репозитории

1. Запушь проект на GitHub.
2. Открой **Settings → Pages**.
3. В разделе **Source** выбери **GitHub Actions**.
4. Запушь изменение в `main` — workflow запустится автоматически.
5. Через пару минут сайт доступен по адресу
   `https://<username>.github.io/<repo>/`.

## Файл .nojekyll

GitHub Pages по умолчанию игнорирует папки, начинающиеся с `_`.
У Sphinx много таких (`_static`, `_sources`). Добавь пустой файл,
чтобы это отключить:

    touch docs/.nojekyll

## Альтернатива: Read the Docs

Read the Docs — специализированный хостинг для документации Sphinx.
Сам собирает проект при push и умеет версионировать сборки.

1. Зарегистрируйся на [readthedocs.org](https://readthedocs.org).
2. Импортируй репозиторий.
3. Создай `.readthedocs.yaml` в корне:

```yaml
version: 2

build:
  os: ubuntu-22.04
  tools:
    python: "3.12"

sphinx:
  configuration: docs/conf.py

python:
  install:
    - requirements: requirements.txt
```

4. Запушь — Read the Docs соберёт проект сам.

## Проверка

- Сделай push в репозиторий.
- Открой вкладку **Actions** на GitHub — должен появиться запущенный workflow.
- Дождись зелёной галочки.
- Открой URL GitHub Pages и убедись, что сайт работает.
